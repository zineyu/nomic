# Coding Agent 初期脚手架规格

> 状态：待审阅 · 输入：`/split` 的唯一实施依据
> 主 issue: #34
> 关联决策：ADR-0001 ~ ADR-0006（`docs/adr/`）、术语表（`docs/glossary.md`）

## 1. 问题陈述

开发者在终端里做编码任务时，需要一个常驻的、可恢复的 AI 编码助手：

- 我在终端打开 nomic，用自然语言交代一个编码任务，它能读代码、改
  文件、跑命令，把进展实时展示给我。
- 我不小心关掉终端、机器重启、甚至 server 崩溃，重开后能接着刚才
  的对话继续，不会丢失已完成的操作、也不会重复执行已发生的副作用。
- 一个任务聊岔了，我可以从任意一处对话分叉出一条新路继续试，旧的
  分支还在。
- 我可以让同事（或我自己的另一个终端）围观会话进展，任何人随时插
  话，消息按顺序生效。

现有的单机 TUI agent 工具把会话状态绑死在进程内存里，崩溃即丢失；
把多路对话、恢复、围观交给用户自己管理， cognitive load 过高。本项
目把「崩溃恢复、长任务续跑、多客户端围观/接管」做成系统原语，而不
是又一个 agent 框架。

## 2. 目标与非目标

### 目标（初期 DoD = 全架构的单会话垂直切片）

交付时端到端可验证：

1. 启动 TUI → 自动拉起常驻 server → 输入任务 → 看到流式输出。
2. agent 调用工具（读/写文件、shell、列目录、内容搜索）完成一个
   真实小改动（如补单测并跑通），过程逐步落盘。
3. kill 掉 server 进程后重开 TUI 连接同一会话：从最后已确认步骤
   继续，不重复执行非 replay-safe 工具的副作用。
4. 从任意消息分叉新会话并独立继续；TUI 以树形展示会话。
5. 两个 TUI 同时连接同一会话：都能看到实时进展，双方输入按到达
   顺序串行生效。

### 非目标

- TUI 以外的客户端（web、IDE 插件）——IPC 协议为未来客户端预留，
  但初期不实现。
- 工具执行审批、命令白名单、沙箱隔离（权限边界仅限工作目录约束）。
- 自动 compaction / 摘要压缩（超限即停，用户分叉续跑）。
- Anthropic 原生等 rig-core 之外的协议适配；rig 之外的第二 LLM
  客户端库。
- SQLite 之外的存储实现（存储 trait 就位即可）。
- 远程/容器执行环境（执行环境 trait 就位即可）。
- 外部副作用类工具（支付、发消息）的端到端幂等——按设计由工具自身
  负责，checkpoint 只保证提交层不重复受理。
- 多用户权限模型：socket 文件权限 0700，仅本机当前用户可用。

## 3. 用户故事

**启动与连接**

- US1：作为用户，我运行 `nomic` 时若 server 未运行，它自动在后台
  拉起并连接，我无感知等待。
- US2：作为用户，我可以用 `nomic server stop` 显式关闭常驻 server。

**对话与工具**

- US3：作为用户，我在 TUI 输入任务后，能看到模型输出的实时流式
  渲染（文本增量、工具调用提示），直到回复完成。
- US4：作为用户，我交代真实编码任务后，agent 能读文件、写文件、
  执行 shell、列目录、搜索内容，并把结果用于后续推理，最终完成
  任务（验收：真实仓库中小改动 + 测试跑通）。
- US5：作为用户，我按 Esc 能取消当前进行中的模型请求或工具执行；
  已落盘的步骤保留，对话停在可继续状态。
- US6：作为用户，遇到网络瞬时错误时系统自动重试（最多 2 次、指数
  退避）；仍失败则在界面展示错误，我可重发消息。
- US7：作为用户，对话接近上下文窗口上限时 agent 停止并提示我，
  我可从任意消息分叉新会话继续。

**持久化与会话树**

- US8：作为用户，我退出 TUI 后重开，能看到本会话历史并选择恢复
  继续对话（或开新会话）。
- US9：作为用户，server 进程被 kill / 崩溃后，我重开 TUI 恢复会话：
  已完成步骤原样保留；标注为可安全重放的工具自动续跑；不可重放的
  工具被标记为 interrupted，其已提交输出回灌模型，不重复执行。
- US10：作为用户，我可以在任意一条消息处把会话分叉成新分支继续
  探索；父子会话相互独立，列表中以树形展示从属关系。
- US11：作为用户，我可以用 CLI 删除某个历史会话。

**多客户端**

- US12：作为用户，我开两个终端连同一会话，两边都实时看到输出进展
  （围观），任一边输入都按到达顺序串行进入对话（接管无需申请）。

**配置与上下文**

- US13：作为用户，我通过环境变量和 `~/.config/nomic/config.toml`
  配置 provider（base_url / api_key / model）、socket 路径、存储
  路径；API key 不进入会话存储与日志。
- US14：作为用户，agent 自动加载工作目录的 AGENTS.md / CLAUDE.md
  注入系统上下文，与内置默认提示协作。

**安全边界**

- US15：作为用户，agent 的所有文件与 shell 操作被限制在会话绑定的
  工作目录内；越界路径（含符号链接逃逸）一律拒绝，界面可见拒绝原因。

## 4. 实现决策

### 4.1 模块划分（crate 粒度）

- **`nomic-core`**：领域模型（消息、工具调用、会话树、事件）与全部
  trait——存储抽象、LLM 适配器抽象、执行环境抽象；IPC 协议消息类型
  定义。不依赖 rig、不依赖 tokio 之外的运行时假设，可被任何客户端
  复用。
- **`nomic-ai`**：rig-core 适配实现。唯一允许出现 rig 类型的 crate。
  对外只暴露 nomic-core 的 LLM 适配器 trait 实现。
- **`nomic-server`**：常驻进程。agent loop（串行：每步先 checkpoint
  落库再推进）、SQLite 存储实现、会话树管理、消息队列、IPC 服务端、
  广播、取消与重试策略、server 生命周期（自动拉起/常驻/stop）。
- **`nomic-tui`**：TUI 客户端。连接 server、渲染流式输出与对话历史、
  会话列表/恢复/分叉/树形展示、输入编辑、Esc 取消。
- 公共决策：Tokio 异步运行时；TUI 用 ratatui；SQLite 用 rusqlite
  （bundled）；序列化用 serde + JSON Lines。

### 4.2 关键接口形态

- **存储 trait**：异步接口，操作对象为领域模型（append 步骤、读取
  会话树、分叉、标记 interrupted 等）；server 全库只经此 trait。
  SQLite 实现内部做 schema 版本迁移管理。
- **agent loop**：单线程串行状态机——`提交消息 → 请求 LLM（流式）→
  工具调用 → 执行 → 结果回灌 → …`，每步完成即 checkpoint。取消经
  协作式中断信号实现；重试仅覆盖网络层瞬时错误（≤2 次指数退避）。
- **工具协议**：每个工具声明名称、JSON Schema 参数、replay-safe
  标记；执行经执行环境 trait 派发，返回结构化结果（成功/拒绝/
  输出）。边界校验（工作目录 lexical 校验 + 符号链接解析）在执行
  环境内统一执行。
- **IPC 协议**：Unix socket（默认 `~/.local/share/nomic/nomic.sock`，
  权限 0700）上的 JSON Lines 双向消息。连接首帧交换协议版本。
  客户端→server：提交消息、取消、订阅会话、列表/恢复/分叉/删除
  会话；server→客户端：事件流（增量、消息完成、工具调用开始/结束、
  错误、会话树）。协议定义在 nomic-core。
- **系统提示构成**：内置默认提示（角色、工具说明、边界约束）+ 启动
  时读取工作目录 AGENTS.md / CLAUDE.md（存在则注入）+ 用户配置
  覆盖。checkpoint 的持久化对象是消息与工具调用步骤，系统提示随
  会话配置记录，恢复时按记录重建。

### 4.3 架构取舍

- **server 唯一写者 + IPC**：多客户端并发、广播、串行化都在 server
  进程内解决；存储选型退化为内部细节（SQLite 单写者无并发瓶颈）。
  代价：任何交互多一次 IPC 跳转，协议是新的长期维护面。
- **逐步 checkpoint 先于执行**：宁可每步多一次写盘，换取崩溃恢复与
  用户 resume 同一条路径（参考 Pi Durable 语义）。代价：loop 吞吐
  略降，对编码 agent 可忽略。
- **树形会话 + 写时复制**：分叉实现简单且符合「试错探索」心智；
  代价是存储随分叉线性增长，初期可接受。
- **无锁消息队列**：无输入权概念，语义最简（先到先得）；代价是
  两人同时插话时顺序可能不符合其中一方的预期，初期接受。
- **rig-core 薄封装**：免费获得 20+ provider 与成熟的 tool calling
  协议层；代价是 pre-1.0 破坏性升级，需锁定精确版本并在升级时
  迁移（风险集中收敛在 nomic-ai 一个 crate）。

## 5. 测试决策

### 主测试 seam：**server 外部边界**（唯一规格级 seam）

在 server 与外部世界之间插入测试替身：LLM 适配器用脚本化替身（按
剧本返回流式 token 与工具调用请求）、执行环境用内存替身；存储用
临时目录上的**真实 SQLite**（走同一存储 trait）。TUI 不进入此 seam，
直接以协议客户端驱动 server。

- **防止**：agent loop 串行/checkpoint 时序错误；回放丢步与重复执行
  副作用；分叉不独立；多客户端消息乱序；取消后状态不可继续；重试
  风暴。
- **漏**（显式接受）：rig 与真实 provider 的协议差异、真实流式行为
  （用一个手动/可选的真实端点冒烟脚本提示，不进 CI 门禁）；TUI
  渲染正确性；真实 LLM 的任务完成质量。
- **覆盖模块**：nomic-server 全部行为 + nomic-core 领域逻辑 +
  SQLite 存储实现。
- **验收标准**（seam 上的端到端断言，全部可在 CI 运行）：
  1. 剧本驱动完成「对话→工具调用→结果回灌→回复完成」，事件序列
     与落库步骤一一对应；
  2. 模拟 server 在工具执行前后崩溃，重放恢复后：replay-safe 工具
     恰好续跑一次、非 replay-safe 工具标记 interrupted 且副作用不
     重复、已提交输出回灌；
  3. 任意消息分叉后双向追加互不可见，树形列表正确；
  4. 两个并发协议客户端交错提交，落库顺序等于到达顺序，双方收到
     相同事件序列；
  5. Esc 取消与重试路径的行为断言。
- **参照既有测试**：仓库当前为骨架（仅 placeholder 测试），无既有
  测试可参照；本 seam 即定义新的行为测试基线，写法遵循 workspace
  的 nextest 约定。

### 次级单元测试（不算规格 seam）

nomic-core 纯函数逻辑（边界校验、提示词组装、协议编解码）随代码
就地单测；TUI 的纯状态逻辑（列表/树形展开）同理。它们不替代主 seam。

## 6. 约束与依赖

**仓库约束**（AGENTS.md，全部硬性）：

- Rust 1.97 / edition 2024；workspace lints：unsafe_code forbid，
  clippy all/pedantic/nursery/cargo 全 deny；`missing_docs = warn`。
- 新 crate 放入 `crates/<category>/<name>/` 并登记 workspace members。
- 提交前必须通过 `check`（fmt / clippy / test / doctest / deny /
  audit / machete / taplo / typos）；单文件 800 行上限。
- 禁止提交密钥与 `.env`；API key 只经环境变量或本地用户配置文件。
- 一切操作在 devenv 环境内进行；版本管理用 jj，推送前整理为原子
  commit。

**外部依赖**（均须过 deny/audit/machete）：

- rig-core（MIT，MSRV 1.95）——LLM 接入，锁定精确版本；
- tokio、serde/serde_json、rusqlite（bundled）、ratatui；
- 新增依赖须确认许可证兼容、维护活跃、无未使用项。

**运行约束**：

- 仅本机单用户：Unix socket 权限 0700，无认证体系。
- SQLite 存储路径默认 `~/.local/share/nomic/`，可配置。
- server 常驻但不自启于系统启动；由首个客户端按需拉起。
