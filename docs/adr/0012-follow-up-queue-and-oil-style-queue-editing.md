# ADR-0012: 排队输入（pi 式 follow-up 队列）与 oil.nvim 式队列编辑

## Status

Accepted（follow-up 队列实现由 [ADR-0014](0014-unified-message-queue.md)
并入统一消息队列；QUEUE 模式交互继续有效）

## Date

2026-08-07

## Context

ADR-0002/0011 确立的 TUI 在 agent 运行中对提交一律拒绝（状态栏提示
「运行中，等待本轮结束」）。长工具调用（测试套件、构建）动辄数分钟，
用户在这段时间里产生的后续指令只能自己记着、等结束后重新输入——这是
编码 agent 交互的最高频摩擦之一。

pi-coding-agent 的解法是**排队输入**：运行中提交的消息进入队列（steering
在下一个工具调用边界插入以「转向」当前运行；follow-up 在当前运行结束后
依次发送），聊天区可见。但 pi 的队列编辑能力很弱，排队消息基本只能
「追加 + 整删」。

oil.nvim 提供了另一个参照：它把目录列表呈现为一个普通 vim 缓冲，用户用
`dd`/`cw`/`J` 等常规编辑操作直接修改列表，保存即应用。「列表即缓冲」的
心智模型与 nomic 已有的 vim-like 交互（ADR-0011）天然契合。

需求：**实现 pi 式排队输入，队列编辑采用 oil.nvim 式缓冲交互。**

## Decision

### 队列语义（pi 式 follow-up）

- **入队**：运行中（含工具执行中）INSERT 下 `Enter`，普通输入与模板调用
  （展开后）连同暂存附件一起入队；本地 slash 命令（`/help`、`/copy` 等）
  照常立即执行；会话命令（`/compact`、`/retry`、`/models` 等要经 driver
  串行修改 agent 上下文）仍拒绝并保留草稿——**队列只承载发给模型的
  prompt**，不承载会话操作。
- **发送（drain）**：一轮 prompt **正常结束**（未被 Ctrl+C 取消、响应未以
  Error/Aborted 收尾——与 goal 模式同一判定口径）后，按 FIFO 逐条自动
  提交。队列优先于 goal 模式追问；排队消息视为用户意图，发送时重置
  goal 连续追问计数。
- **异常暂停**：运行被取消或失败时队列保留不发送，输入框标题提示
  「队列暂停 N 条」；空闲下 `Enter`（空草稿）发送下一条，或 Esc→Q 编辑
  后退出即恢复。
- **会话切换清空**：`/new`、`/resume`、`/tree` 分支切换会清空队列——
  排队消息是旧上下文的后续意图，不应带进新对话。

不实现 pi 的 steering 队列（运行中插入转向消息）：需要 core agent 的
turn 边界注入支持（agent.rs 的 M1 裁剪项），是独立的后续增量；follow-up
已覆盖「排队等结束」的主要诉求。

### QUEUE 模式（oil.nvim 式编辑）

新增 `Mode::Queue`（ADR-0011 模式家族第六个模式），NORMAL 下 `Q` 进入
（队列为空或草稿非空时拒绝并提示）。**输入框即队列缓冲**：排队消息逐条
渲染为缓冲行（多行消息展开多行、附件以 `🖼×n` 标示），用户以 vim 肌肉
记忆直接修改：

| 键位 | 行为 | oil.nvim/vim 对应 |
|---|---|---|
| `j`/`k` `gg`/`G` | 移动条目游标 | 缓冲行导航 |
| `i`/`a`/`Enter` | 就地编辑游标条目（草稿缓冲即条目内容） | 光标行进入插入 |
| `o`/`O` | 下/上方插入空条目并就地编辑 | `o`/`O` 开新行 |
| `dd`/`x` | 删除条目 | `dd` 删行 |
| `J`/`K` | 条目下移/上移一位（换位） | `:move` |
| `Esc` | 保存并退回 NORMAL | 回到 NORMAL |

编辑子状态复用 INSERT 的全部缓冲编辑键（词级移动/删除、Shift+Enter 多行、
Ctrl+V 粘贴），`Enter`/`Esc` 保存写回槽位；保存空文本即删除该条目
（oil.nvim 空行忽略语义），编辑不移动条目位置、保留其附件。编辑子状态下
slash 补全不启用（编辑的是消息文本而非命令），`Enter` 恒为保存。

**QUEUE 打开期间冻结 drain**：用户正在手持缓冲编辑，运行正常结束也不
发送，避免队首在用户编辑途中被弹走导致下标漂移；退出 QUEUE 即恢复
（空闲立即提交队首，运行中等本轮结束后自动继续）。

### 视觉与反馈

- 输入框内容顺序：附件行 → 队列区 → 草稿行；队列条目以 `»` gutter
  标示（暗色），QUEUE 游标条目以 `❯` + accent 标出；内容区行数上限
  由 5 提高为 10（附件 + 队列 + 草稿共用），超出内部滚动跟随光标。
- 输入框标题：运行中追加「N 条排队（Esc→Q 编辑）」；空闲且队列暂停
  时提示「队列暂停 N 条 · Enter 发送下一条」；QUEUE 模式下显示队列
  键位（运行中叠加 spinner）。
- 状态栏：` QUEUE ` 反色蓝块徽标（与 INSERT/NORMAL/VISUAL 色相区分），
  右侧键位提示随导航/编辑子状态切换。
- 光标形状：QUEUE 导航 = 实心块（不可键入的浏览态），就地编辑 = 竖条，
  与 ADR-0011 的情境信号一致。

### 代码落点

- `app.rs`：`QueuedMessage`（文本 + 附件）、`queue: VecDeque`、
  `queue_cursor`、`queue_editing`；`press_enter_running` 改为入队分发；
  `drain_queue`（FIFO + freeze 判定）；QUEUE 模式键位（导航/编辑两个
  子状态）；INSERT 与 QUEUE 编辑共用 `apply_edit_key`。
- `mod.rs`：`handle_prompt_done` 接入 drain/暂停裁决（异步化以接线
  提交效果）；光标形状按「块/条」语义判定（覆盖 QUEUE 子状态切换）。
- `ui.rs`：队列区渲染、输入框高度与标题、QUEUE 徽标与提示。
- 全部逻辑在 TUI 状态层，core crate 与 driver job 协议零改动。

## Non-goals

- steering 队列（运行中转向）：依赖 core agent 的 turn 边界消息注入，
  后续独立增量。
- 排队 slash 命令（如把 `/compact` 排到本轮后执行）：队列只承载 prompt
  文本；会话命令的排队语义（上下文先后、失败处理）需单独设计。
- 跨会话持久化队列：队列是内存态，TUI 退出即丢弃。
- 条目的寄存器/剪贴板操作（`yy`/`p`）：删除即丢弃，需求出现再议。

## Consequences

- 运行中 `Enter` 从「拒绝 + 提示」变为「入队」：旧提示测试与文档同步
  更新；用户不再丢失运行中产生的输入意图。
- 空闲 `Enter`（空草稿）在队列暂停时语义为「发送下一条」——原语义为
  无操作，无回归风险但属于新魔法，已在输入框标题与 `/help` 中明示。
- `Mode` 新增变体，模式分发、徽标、光标形状、渲染各多一个分支；
  队列编辑复用既有缓冲编辑与滚动机制，新增测试全部在纯状态层。
- 输入框内容上限从 5 行升至 10 行（队列可见时），长队列会暂时占用
  更多聊天区高度，由内部滚动兜底。
- 后续 steering 队列落地时，QUEUE 模式的编辑交互可直接复用
  （队列语义扩展为双队列）。
