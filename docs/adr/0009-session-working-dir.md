# ADR-0009: 会话绑定工作区标识（受理携带 working_dir）

## Status

Accepted

## Context

规格要求目标为新建会话的提交在受理时创建绑定工作目录的会话
（工具边界以它为基准，见 US15），但受理请求（Submission）最初
没有携带工作目录：New 目标无法构造合法会话——没有工作目录的
会话是非法状态，工具边界失去依据，不能用空路径占位再补。

设计讨论中出现过另一种思路：会话绑定执行环境（env），由 env
解释工作空间。参照 Pi durable 的做法否决了它：

- Pi 的会话头持久化 `cwd`，分叉继承同一标识，cwd 同时注入系统
  提示——「会话绑定工作目录」是持久化的领域事实；
- Pi 的隔离（容器、沙箱、micro-VM）是进程级或部署级的：整个
  Pi 进程在隔离环境内运行，或部署时配置工具路由；会话文件里
  没有任何 env 引用；
- 因此持久化的路径不是「server 本地路径的断言」，而是工作区
  标识，坐标系由运行它的进程环境解释（容器内 `/workspace` 是
  容器视角的路径）。

## Decision

Submission 携带 `working_dir: PathBuf`。目标为新建会话时服务端
据以创建会话；目标为既有会话时暂不消费该字段。工作目录是会话
的领域状态：随会话持久化、分叉继承、恢复时重建工具边界。它是
工作区标识而非本地路径断言，坐标系由 ExecutionEnvironment 解释；
恢复会话假定同一部署环境。执行环境的可替换性（本地、远程、
沙箱）由派发层解决，会话模型不感知 env；若未来出现多 env 并存，
会话身份届时可增加 env 维度（独立演进点）。

## Consequences

- IPC 协议的 Submit 帧与 nomic-core 的 `Submission` 增加
  `working_dir` 字段；既有客户端构造处同步更新。
- `Session::restore` 成为存储实现从库中回放构造会话的公开路径，
  与 SessionTree 的内存构造路径并列。
- 主 issue #34 §4.2 增补「提交受理」条目，记录 requestId 去重、
  目标会话与 working_dir 的受理语义。
