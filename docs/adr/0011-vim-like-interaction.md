# ADR-0011: vim-like 交互模式重构

## Status

Accepted

## Date

2026-08-05

## Context

ADR-0002 确立的 TUI 是**无模式（modeless）**设计：输入框永远聚焦，多上下文
通过按键重载处理。随着功能增长（补全弹层、四类 picker、运行中本地命令），
重载的规则层次越来越深：

| 按键 | 语义 1 | 语义 2 | 语义 3 |
|---|---|---|---|
| `Esc` | 关闭补全弹层 | 取消运行 | （picker 中）关闭选择器 |
| `↑/↓` | 补全弹层移动选中 | 滚动聊天区 | （picker 中）移动选中 |
| `Enter` | 填入补全候选 | 提交 prompt | 执行 slash 命令 |

UX 层面的问题：

- **按键语义依赖隐式上下文，用户无法预判**。优先级规则（弹层 > 运行 > 空闲）
  只存在于 `App::press` 的路由代码里，用户只能靠试错学习；
- **聊天区是「只读壁画」**：无法用键盘定位消息、复制某段代码块或工具输出，
  唯一出口是 `/copy`（仅最新一条）与鼠标。对编码 agent，「从历史取回一段
  diff/命令」是高频需求；
- **长 prompt 编辑能力弱**：仅逐字符 ←/→/Backspace/Home/End，无词级移动/删除；
- **picker 已是事实上的模式但被实现成特例**（`press_picker` 已支持 j/k），
  说明模式需求在代码中已自然萌发，只是未上升为统一架构。

重构的本质不是「加键位」，而是**把隐式模式显式化**——这正是 vim 交互哲学
的核心。已与需求方确认方向：先出本 ADR，再分期实施。

## Decision

### 设计原则

1. **模式是一等状态**：任何时刻用户能一眼看到当前模式；每个按键在当前
   模式只有一个语义。
2. **渐进式采用**：不懂 vim 的用户零成本（默认落 INSERT，箭头/鼠标/Enter
   照常）；vim 用户获得完整肌肉记忆支持。
3. **`Esc` 永远安全**：语义统一为「退回一层」，任何情况下按 Esc 无损。
4. **改动收敛在状态层**：`App::press` 已是纯状态分发，模式重构为内聚改动，
   不碰 agent/driver 与 core crate。

### 模式架构

```
               ┌──────────────────────────────────────────┐
  启动 ──►  INSERT ⇄ ── Esc（空闲时）──► NORMAL            │
               │  ▲                        │  │           │
               │  │ i / a / Enter          │  │ :         │
               │  │                        ▼  ▼           │
               │  └────── Esc ─────── COMMAND（预填 /）     │
               │                                          │
               └─── 任意模式触发 /resume /models /tree ──► PICKER
                                             ◄── Esc/q ────┘
```

| 模式 | 进入方式 | 职责 |
|---|---|---|
| **INSERT**（默认） | 启动即在此；NORMAL 下 `i`/`a`/`Enter` | 编辑与提交 prompt；slash 命令；Tab 补全 |
| **NORMAL** | INSERT 空闲时按 `Esc` | 浏览聊天区、消息间跳转、复制、搜索、进入命令 |
| **COMMAND** | NORMAL 下 `:`（输入框预填 `/`） | 复用现有 slash 命令与补全 |
| **PICKER** | `/resume`、`/models`、`/tree` | 现有选择器，增强为完整 vim 导航 |

**默认落 INSERT 而非 NORMAL**：这是对话工具而非编辑器，用户进来的第一动作
是打字；vim 的「默认 NORMAL」会制造每次启动多按 `i` 的摩擦。INSERT-first 是
aichat、lazygit 等 TUI 的共同选择。

### INSERT 键位

保留现有全部行为，新增 readline 系词级编辑（不离开插入模式获得主要编辑
效率）：

| 键位 | 行为 | 备注 |
|---|---|---|
| `Esc` | 退回栈（见下） | 语义变化 |
| `Ctrl+W` | 删除前一个词 | 新增 |
| `Ctrl+U` | 清空当前行 | 新增 |
| `Alt+B` / `Alt+F` | 按词左/右移 | 新增 |
| `Ctrl+A` / `Ctrl+E` | 行首/行尾 | 新增（与 Home/End 等价） |
| Enter / Tab / Shift+Enter / 箭头 / Ctrl+V 粘贴 | 不变 | |

### NORMAL 键位（本次重构的核心价值区）

滚动与跳转：

| 键位 | 行为 |
|---|---|
| `j` / `k` | 上/下滚动一行（箭头与滚轮在所有模式照常可用） |
| `Ctrl+D` / `Ctrl+U` | 半页下/上滚 |
| `gg` / `G` | 跳到最早/最新（`G` 即回到跟随模式） |
| `[m` / `]m` | 跳到上一条/下一条消息（user/assistant 边界） |
| `[t` / `]t` | 跳到上一个/下一个工具调用（快速巡检 agent 行为） |

复制（yank）：

| 键位 | 行为 |
|---|---|
| `yy` | 复制当前消息全文到剪贴板 |
| `yc` | 复制当前消息中消息游标处的代码块 |
| `Y` | 复制最新一条 assistant 消息（等价现有 `/copy`） |

搜索与命令：

| 键位 | 行为 |
|---|---|
| `/` | 聊天内容搜索（输入框复用为搜索框，实时高亮，`n`/`N` 跳下一个/上一个） |
| `:` | 进入 COMMAND（输入框预填 `/`，复用补全弹层） |
| `i` / `a` / `Enter` | 回 INSERT（光标置于输入末尾） |
| `Ctrl+C` | 取消运行 / 退出（全局保留；`Ctrl+D` 在 NORMAL 让位半页滚动） |

**`/` 冲突裁决**：slash 命令只在 INSERT 中通过字符输入触发；NORMAL 中输入
框不聚焦，`/` 让给搜索。两个语境不重叠。

**`Enter` 在 NORMAL 的语义**仅为回 INSERT：不设「重发上一条」等魔法。提交
是有副作用的动作，必须只在 INSERT 显式发生。

**`q` 不绑定退出**：vim 中 `q` 是宏录制，且对话工具误退代价高。退出保持
`Ctrl+C`/`Ctrl+D`/`/quit`。

### COMMAND 键位

技术上即「INSERT + 预填 `/`」，行为与现有 slash 命令完全一致（Tab 补全、
Enter 执行、Esc 回 NORMAL）。收益是 vim 用户的 `:` 肌肉记忆直接可用，实现
成本接近零。

### PICKER 增强

在现有 j/k/Enter/Esc/q 之上补齐：

| 新增键位 | 行为 |
|---|---|
| `gg` / `G` | 跳首/尾 |
| `Ctrl+D` / `Ctrl+U` | 半页翻 |
| 直接打字 | 过滤候选（picker 内嵌过滤输入行）——长 session 列表与模型列表的质变改进 |

### `Esc` 退回栈（最重要的一处语义统一）

现状 Esc = 关弹层，否则取消运行。vim 化后 Esc 增加「回 NORMAL」。统一为
严格的退回栈，每层无损：

```
Esc：
  1. 补全弹层开着？     → 关弹层（留在 INSERT）
  2. 有运行中任务？     → 取消运行（留在 INSERT，输入不丢）
  3. 皆否且处于 INSERT  → 回 NORMAL
  4. NORMAL / COMMAND / PICKER → 回上一层（最终落 INSERT）
```

理由：取消运行是「停止当前活动」，回 NORMAL 也是「退出当前活动」，语义同向
不冲突；运行中狂按 Esc 不会误入 NORMAL 后用 j/k 污染输入。代价：取消运行后
需多按一次 Esc 才能进 NORMAL——可接受，「取消」与「浏览」很少是连续意图。
`Ctrl+C` 作为全局取消/退出保留，给非 vim 用户兜底。

### 视觉反馈

模式必须可见，这是「显式化」的另一半：

1. **状态栏左侧模式徽标**（与现有模型徽标并列，airline 风格）：
   ` INSERT `（accent）/ ` NORMAL `（对比色）/ ` SEARCH `（warn）。
2. **光标形状切换**（crossterm `SetCursorStyle`）：INSERT = 竖条，
   NORMAL = 实心块。vim 用户最强的情境信号，成本极低。
3. **输入框边框语义叠加**：现有三态（运行中黄/补全 accent/空闲暗）保留；
   NORMAL 时输入框降为暗色，聊天区当前消息 gutter 高亮 accent 作为
   「消息游标」（`]m`/`[m` 移动它，`yy` 复制它）。
4. **状态栏右侧键位提示随模式切换**：
   - INSERT：`/ 命令 · Tab 补全 · Enter 发送 · Esc 浏览`
   - NORMAL：`i 输入 · j/k 滚动 · ]m 跳消息 · yy 复制 · / 搜索 · : 命令`

### 可发现性

- `/help` 输出按模式分组列出键位（命令注册表仍是单一来源，扩展键位表）；
- 首次进入 NORMAL 时状态栏一次性提示「已进入浏览模式」**已移除**（后
  续修订：模式徽标与右侧键位提示已足以表达当前模式）；
- 欢迎页键位简介更新为两行（INSERT 一行、NORMAL 一行）。

### 代码落点

- `app.rs`：新增 `enum Mode { Insert, Normal, Picker }`（COMMAND 作为
  Insert+预填实现，不单列变体）；`press` 改为按 `Mode` 分发——现有
  `press_picker` 特例路由被模式路由收编；消息游标状态（选中条目索引）。
- `mod.rs`：`SetCursorStyle` 随模式切换；`map_key` 补充 Alt 修饰映射。
- `ui.rs`：模式徽标、分模式键位提示、消息游标 gutter 高亮。
- 测试：状态层模式迁移表驱动单测；ui 用 `TestBackend` 快照冒烟（沿用
  ADR-0002 既定口径）。

### 实施路线（每期独立可交付、可回滚）

- **Phase 1 — 模式骨架**：`Mode` 枚举与分发；NORMAL 基础导航
  （j/k、Ctrl+D/U、gg/G、`i`/`Enter` 回 INSERT）；`Y` 复用 `/copy` Effect；
  模式徽标 + 光标形状 + 分模式提示；INSERT 词级编辑。
- **Phase 2 — 内容操作**：消息游标 + `[m]m`/`[t]t`；`yy`/`yc`；NORMAL `/`
  搜索；PICKER 增强（gg/G、过滤）。
- **Phase 3 — 深度 vim（按反馈决定）**：VISUAL 逐行选择复制；NORMAL 下对
  草稿缓冲的 normal-mode 编辑（`dd`/`x`/`dw`/`A`）；`:set` 运行时配置。

## Non-goals

- 完整 vim 模拟器（寄存器、宏、mark、文本对象）。目标是「vim-like」，
  借模式哲学与核心肌肉记忆，不复刻 vim 全集。
- 可配置键位映射（keymap 配置文件）。先锁定一套合理默认，需求出现再议。
- NORMAL 下直接提交/重发消息（提交只在 INSERT 发生，见上）。
- print 模式与 core crate 的任何改动。
- Phase 3 各项均为非承诺项，按 Phase 1/2 落地后的反馈决定。

## Consequences

- `Esc` 语义变化：老用户「Esc 取消运行」仍在退回栈第 2 层生效，但空闲时
  Esc 从「无操作」变为「进 NORMAL」。README 键位说明与 `/help` 同步更新。
- 非 vim 用户路径完全保留（INSERT 默认、箭头/滚轮全模式可用、Ctrl+C 兜底），
  误入 NORMAL 有显眼徽标与一次性提示。
- `App` 状态增加 `mode` 与消息游标字段；`Key` 枚举增加 Alt 修饰与
  `gg` 等多键序列的输入状态（pending key），测试面增大但仍在纯状态层。
- picker 过滤（Phase 2）为 `/resume` 与 `/models` 带来独立于 vim 化的
  普遍体验收益。
- 后续增强（VISUAL、keymap 配置）均在 `tui/` 模块内演进，不影响 core。

## Amendments（现状修订，不改写历史决策）

### 2026-08-05：Phase 1–3 全部落地，实现期设计裁决记录

三个 Phase 均已实现（VISUAL 与草稿编辑两项 Phase 3 承诺项落地；`:set`
 维持 Non-goal——ADR 仅给出「如 set wrap」的示例，需求未具体化，
 待真实需求出现再设计）。实现期对正文的偏离与裁决：

- **picker 导航语义修正**（偏离正文表格）：正文写 `gg`/`G` 跳首尾 + 直接
  打字过滤，二者冲突（`g`/`G` 是合法过滤字符，如过滤「GPT」「debug」）。
  落地采用纯 fzf 语义：可打印字符一律过滤；导航 = ↑/↓、Ctrl+N/P 移动、
  Home/End 跳首尾、Ctrl+D/U 半页翻。`q` 关闭取消（同为过滤字符），关闭
  统一走 Esc（先清过滤、再关闭）。这与本 ADR 「一键一义」原则一致。
- **NORMAL 中 `Ctrl+D` 让位半页滚动**（正文已修订）：取消/退出在 NORMAL
  统一由 `Ctrl+C` 承担。
- **VISUAL 粒度为消息而非逐行**（正文「逐行选择」的语义收窄）：聊天内容
  以消息（条目）为自然边界，逐行选择需要额外的行游标基础设施而收益不明；
  `V` 以消息游标为锚点，`j`/`k` 按消息扩展，`y` 复制范围。
- **COMMAND 不预填覆盖草稿**：NORMAL `:` 在草稿非空时只回 INSERT 并提示，
  不覆盖用户未发送的文本。
- **picker 弹出时机**：picker 只能在 INSERT 经 slash 命令触发，打开时
  模式字段必为 INSERT，关闭后回到 INSERT。
- **运行中不可进 NORMAL**（正文既定取舍确认）：Esc 退回栈保证运行中 Esc
  先取消；浏览运行中输出用箭头/PgUp/PgDn/滚轮（全模式可用）。

### 2026-08-06：Esc 语义收窄为纯模式切换

正文「Esc 退回栈」第 2 层（运行中取消）与上一条修订「运行中不可进
NORMAL」一并废止：

- **Esc 一律是模式切换，不再终止输出**。INSERT 中 Esc 退回栈只剩两层：
  关补全弹层 → 回 NORMAL；运行中同样直接进 NORMAL 浏览（草稿与运行
  均不受影响）。取消运行统一由 `Ctrl+C` 承担（INSERT/NORMAL 同口径）。
- 动机：「一键一义」。原栈中 Esc 在运行中具有破坏性（中断输出），与其
  余各层的无损语义不一致；浏览运行中输出是高频需求，不应以取消运行为
  前置代价。Ctrl+C 取消/退出本就是全局兜底，语义收拢后 Esc 在任何时刻
  都可放心连按。
- 连带：输入框运行中标题改为「运行中 · Ctrl+C 取消」；README 键位说明
  同步更新。
