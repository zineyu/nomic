# ADR-0010: SQLite 存储模型

## Status

Accepted

## Context

存储 trait（S1 落地）要求首个 SQLite 实现覆盖：受理台账去重、
步骤追加与回放、会话树读取、任意消息分叉、interrupted 标记、
调度器的待处理查询与 schema 版本迁移。落地前需要决定持久化
形态：会话内容与执行日志的关系、分叉复制什么、迁移如何组织、
同步 rusqlite 如何接入异步 trait。

## Decision

- **双写两表**：`messages` 是会话内容（模型上下文，分叉的复制
  单位）；`steps` 是执行日志（checkpoint 单元，恢复与事件对应
  关系）。消息步骤在两表同写；工具调用步骤只写 steps。
- **整体 JSON 落库 + 查询维度投影**：领域对象整体经 serde 序列化
  存 `body` 列；id、状态、步骤类别（kind）、关联调用/消息以独立
  列投影，SQL 不解析 JSON 体。步骤类别的字符串编码以 `KIND_*`
  常量为唯一事实源。
- **写时复制分叉复制完整步骤前缀**：fork 复制来源会话截至
  分叉点（含）的完整步骤前缀——消息行、消息步骤与它们之间的
  工具执行步骤（序号重排为稠密序列）。子会话只在分叉点之后
  重新起算执行日志；父会话已完成的工具调用属于共享历史，
  不重放。
- **迁移链管理 schema**：`user_version` pragma 记录版本，迁移按
  版本升序在一个事务内应用；高于当前实现的版本拒绝打开。迁移
  测试以 fixture SQL 固化旧版本 schema 契约（旧 release 写出的库
  可打开且数据完好）。
- **单连接 + 互斥锁 + spawn_blocking**：rusqlite 为同步接口，全部
  操作在阻塞线程池执行，连接互斥锁串行化写（SQLite 单写者语义），
  trait 保持异步形态；多步写路径在事务内完成存在性检查。
- **显式缺失与非法状态**：不存在会话的步骤读取返回
  `StorageError::NotFound`（空 vec 不做哨兵）；已完成的调用不可再
  标记 interrupted；工作目录非 UTF-8 在存储边界显式失败。

## Consequences

- 分叉会话的步骤序列是父日志截至分叉点的忠实前缀：重放子
  会话可完整重建模型上下文，含父会话已完成的工具执行记录；
  分叉点之后的工作在子会话内重新起算。
- 新增步骤类别时需同步 `KIND_*` 常量与 `mark_interrupted` 的
  生命周期判定（已派发且未完成才可标记）。
- 调度器依赖的领取原子性（Pending → Running）由单写者与条件
  UPDATE 保证；多客户端并发领取经存储串行化。
